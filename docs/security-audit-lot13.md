## Secrets, sorties et appels réseau

Le scan arbre et historique examine les objets Git, sans imprimer les valeurs. Trois chaînes sont des fixtures publiques identifiées : deux secrets nommés test-only et le vecteur RFC 6238 ; exceptions strictes valeur + chemin, jamais un dossier de tests entier. Les clés générées sous `.local` (0600) sont des fichiers privés de développement ignorés, pas des secrets Git. Les exemples PostgreSQL/Redis/S3 sont explicitement locaux et doivent être refusés en production.

Sorties runtime : logs structurés codes/IDs ; exceptions HTTP centralisées sans stack/SQL. Les commandes `dev:access`, `dev:totp`, `iam:dev` exposent intentionnellement des accès locaux à leur opérateur : elles restent DEV/TEST et les sorties de certification sont capturées dans `.local`, jamais publiées. `infra-check` n'affiche que des états. Pas de dump environnement/credentials.

Appels sortants runtime : PostgreSQL/Redis/S3 configurés côté serveur ; API Brevo destination constante ; Next rewrite vers API_INTERNAL_URL configuré serveur ; navigateur vers chemins `/api/v1`. Aucun upload multipart métier ni URL utilisateur arbitraire à récupérer identifié. Les PDF interdisent les requêtes réseau et exécutent sans JavaScript. Pas d'usage applicatif `dangerouslySetInnerHTML` identifié. Les redirects de Next/i18n et navigation auth sont internes ; pas de callback client servant d'URL serveur identifié.

Variables : inventaire généré en annexe ; aucune variable serveur sensible ne doit porter NEXT_PUBLIC_. Les clés IAM, CSRF, MFA, messaging doivent être indépendantes. Aucune migration historique ne doit changer.

## Constat complémentaire issu de la revue approfondie

Reports et Dashboard convertissaient un `Error.message` arbitraire en code HTTP public (gravité High : risque de fuite SQL/credentials). Ils utilisent maintenant une liste fermée de codes attendus et un code indisponible générique pour les erreurs inconnues. Un canari déclenche ces deux chemins et vérifie l’erreur publique. Le rapport de certification précise les commandes et résultats finaux.

La vérification finale Next inclut aussi la cohérence de l’origine API entre le build et le runtime : une valeur de démarrage sûre ne peut plus masquer une réécriture locale compilée. `@gestschool/config` est disponible dans les dépendances production du web. Les résultats finaux, échecs initiaux et leur correction figurent dans `lot13-certification.md`.
